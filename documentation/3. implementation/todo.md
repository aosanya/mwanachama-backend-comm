| W14 | P1 | 📋 | 🐞 **BUG — a DM thread's last admin can permanently strand every remaining participant with no admin at all, and `Kick` has no guard against kicking yourself.** Demonstrated directly against `DMStore` (sqlite, in-process; `TestKick_PinsSoleAdminCanKickThemselves`/`TestKick_PinsSelfKickedSoleAdminHasNoWayBackIn`/`TestLeave_PinsLastAdminLeavingStrandsRemainingParticipants`, `routes/w14_dm_admin_lockout_test.go`). Narrowest form: `dm_roster_impl.go`'s `Kick(threadID, actorID, byActorID)` never checks `actorID != byActorID`, so a sole admin can call `Kick(th, "admin-1", "admin-1")` and it succeeds (`err == nil`), leaving their own row `state=kicked`. Broader, more realistic form: an ordinary `Leave` by the thread's only admin, while another non-admin participant is still active, produces the identical stranding — `Leave` has no "you are the last admin" guard at all. Either way, **there is now no way back in for anyone**: `Promote` requires `isAdmin(by)` (fails — nobody is an active admin any more); `ReEnable`'s by-admin path has the same requirement; `ReEnable`'s self-service path (`memberID == by`) only accepts the caller's own row in `DMStateLeft` *and* only when `!hasActive(threadID)` (nobody else active) — never satisfied once another participant remains, and never satisfied at all for `DMStateKicked`. `routes/dm.go`'s `KickDM` passes the caller-supplied `body.ActorID` straight to `dm.Kick` with no check against `identity.CallerID(r)` either, so the gap is reachable through the real HTTP route, not just the store method. **Fix location**: `dm_roster_impl.go`'s `Kick` (refuse `actorID == byActorID`) and `Leave` (refuse — or require a successor — when the leaving actor is the thread's last active admin and other participants remain active); the exact refusal shape (a new sentinel, or reusing `ErrDMNotLastToLeave`) is a design call, not made here. Found 2026-09-16 by the fleet integration-test sweep (loophole catalogue #10: an allowed action whose *state afterward* is unrecoverable). Three pinning tests committed in `routes/w14_dm_admin_lockout_test.go` asserting the *current* broken behavior — each documents in its own comment what must change once fixed. `go test ./...` and `go test -tags=integration ./...` both green with these added. |
